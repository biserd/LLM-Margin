# Daily SEO in local Codex

Use `$seo-autopilot`, `$blog-refresher`, and `$seo-title-optimization` every run. Read their pinned instructions under `.agents/skills/`, the product context, keyword map and recent SEO records. The production site is https://llmmargin.com. Use the existing local checkout, GitHub login, and Wrangler login. The owner authorizes publishing qualifying edits. Skip upstream approval, outreach, purchases, and drafts.

For browser work, use the existing Chrome tabs and signed-in Chrome profile by default, including Search Console, Analytics, and Google Search. Open a new Chrome tab in that profile when necessary. Operate the UI autonomously within the authorized task. Do not default to the in-app browser or ask the owner to navigate, export reports, provide screenshots, or supply API credentials for data accessible through the signed-in browser. Ask for owner involvement only when a genuine login, MFA, or permission requirement cannot be completed with the existing session.

1. Run `python scripts/seo/research.py` from the LLM Margin repo and inspect the findings. Also run `node artifacts/tokencalc/scripts/verify-rendered-seo.mjs` and record the status, checked views and findings from `.seo-work/rendered.json`. This opens public pages in an isolated headless Chrome and checks titles, descriptions and canonicals after JavaScript loads and during in-app navigation. Exit code 1 means verified findings. Exit code 2 means checks were incomplete. Use connected sources and built-in web search where available. When API evidence is unavailable or incomplete, read Search Console through the existing Chrome login; use the linked Analytics Search Console reports as a fallback. Check indexing and AI visibility only with direct evidence of the relevant surface. Keep unavailable data marked unchecked. Maintain the keyword map and flag overlapping intent. Fix verified production issues. Add a comparison only when its distinct intent and claims have evidence.

   If the headless browser is unavailable or a check is incomplete, repeat the affected public checks in the existing Chrome profile with the browser tool. Use the same routes and link sequence defined in the script. After the route heading renders, inspect `document.head` for exactly one `title`, `meta[name="description"]` and `link[rel~="canonical"]`, compare the title and description with the direct response, and confirm the canonical is the absolute public URL for the active path. To test in-app navigation, start on the quote calculator, click the Pricing navigation link, then follow the Blog and guide links. Confirm the path and rendered head switch on the same document. Record the Chrome fallback, URLs, values, findings, and any routes that still could not be checked. Continue the SEO run without waiting for credentials or manual browsing. Reuse this fallback for incomplete post-deploy checks.

   When AI Overview measurements are unchecked and signed-in Chrome is available, search the five saved AI visibility prompts in `seo/queries.json` through the Google Search UI. Record the visible AI Overview, brand mentions and cited URLs for each prompt. Keep ordinary search results outside the AI citation observations. Label the browser session and any personalization or incomplete results. Record unavailable answer surfaces as unchecked.
2. Check for a blog refresh using the latest available Search Console page/query data. Apply the positions 8–20 rule and inspect the top three current results. Without qualifying data, record the skip. Preserve URL and voice.
3. Review SEO titles and H1s against rendered pages, the keyword map, product behavior, and current search results. If Search Console is connected, use the latest complete 28 days and compare CTR by position and device. Otherwise publish clear editorial fixes, such as a missing, misleading, duplicate, stale, or mismatched title or H1. Record the specific issue and leave CTR, impressions, clicks and rank unchecked. Combine changes to the same page and skip rewrites of titles pending measurement. A day with no qualifying edits is valid.

Use a clean, current checkout based on GitHub main. If another run is active or the checkout contains unrelated changes, leave those changes alone and log the reason. Before a release, record the current production Worker version and expected title, H1, canonical or body change for each URL. Run `pnpm build`, inspect the built HTML, run `node artifacts/tokencalc/scripts/verify-rendered-seo.mjs --dist`, and run relevant repo tests. Push only verified changes. Then run `pnpm exec wrangler deploy` using the existing login and verify the live URLs with `node scripts/verify-public.mjs` and a fresh rendered SEO check. If repeated checks confirm a regression caused by the release, restore the previous Worker version and revert only the job's own commit.

Commit a concise dated record under `seo/runs/` with the three stage outcomes, sources or blockers, before and after metadata and metrics where measured, changed URLs, and deployment status. Keep a title measurement pending for 28 complete post-release days when baseline data exists. For editorial title fixes without data, wait at least 28 days before revisiting unless correcting a verified regression. Use scoped permissions available to the task and report any exact deployment or network restriction that prevents completion.
