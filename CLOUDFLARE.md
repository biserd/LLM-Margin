# LLM Margin on Cloudflare

LLM Margin runs as one Cloudflare Worker:

- the Vite/React site is served with Workers Static Assets;
- `/api/*` requests are handled by the Worker;
- users, one-time codes, and rate limits are stored in D1;
- one-time sign-in codes are sent through Cloudflare Email Sending;
- subscriptions are managed through Stripe's HTTP API.

No continuously running Node.js server or PostgreSQL service is required.

## Client-quote product and agent access

The homepage targets AI freelancers and small agencies. `/ai-service-pricing-calculator` is a free deterministic estimate; signed-in users can save up to 100 private drafts. A $29 Stripe Checkout payment unlocks printable client-proposal HTML and an internal CSV for one quote and its revisions. Existing active/trialing Pro accounts retain exports without another purchase. The original simulator remains at `/margin-calculator`.

`migrations/0002_quotes.sql` is additive: quotes, idempotent checkout attempts, confirmed purchases, and a refund-reversal ledger. It does not rewrite existing users or subscriptions. Payment fulfillment validates ownership, currency, amount, and paid status, and is safe against duplicate or out-of-order refund events. Stripe must deliver `checkout.session.completed`, `checkout.session.async_payment_succeeded`, `checkout.session.async_payment_failed`, and `charge.refunded` in addition to the existing subscription events. `node scripts/check-stripe.mjs` checks configuration; `--apply-webhooks` adds missing events without removing existing ones. `--checkout-smoke` creates and immediately expires an unpaid checkout; never enter payment details for that check.

Public estimation is exposed through `/api/estimate`, `/mcp`, and `/a2a`. Private quote access uses OAuth 2.1 with PKCE, explicit website consent, scoped tokens, one-hour access tokens and optional 30-day refresh tokens. Tokens and clients live in the `OAUTH_KV` namespace. Users can revoke grants in `/account`. Agents cannot initiate checkout, charge cards, or email proposals. OAuth client metadata fetches use `global_fetch_strictly_public` to restrict private-network access.

Public pages support `Accept: text/markdown`; the root also supports `Accept: application/json` for the organizational agent index. Discovery files, OpenAPI, skill digests, Content-Signal and Link headers are generated by the Worker. Browser WebMCP is progressive enhancement and requires a supporting browser. Web Bot Auth is deliberately not advertised: there is no outbound browsing agent to authenticate.

DNS-AID publication is additive and does not alter apex/www or email routing. `node scripts/agent-dns.mjs` prints the plan. `--apply` needs `CLOUDFLARE_API_TOKEN` with Zone Read and DNS Edit scoped to llmmargin.com. It verifies existing records and refuses conflicting overwrites. The existing Wrangler OAuth credential does not have DNS permissions.

```shell
pnpm exec wrangler d1 execute llm-margin-local-tests --local --config tests/wrangler.jsonc --file tests/seed.sql

node --test tests/quote-model.test.mjs tests/integration.test.mjs

```

The test config is separate from production so it cannot load the root `.dev.vars`. Never run test fixtures or synthetic signed webhooks against production. Production checks should use public discovery and estimate endpoints only. A Worker rollback can use the previous deployment version; leave the additive quote tables and OAuth namespace intact during rollback.

## Homepage accessibility and performance

The homepage uses its prerendered HTML, inline route-specific Tailwind styles, a bundled Inter font with `font-display: optional`, and a 1.7 KB first-party navigation enhancement. Native links and the mobile details menu work without React or JavaScript. The calculator and other application routes still load the full React application; the small homepage entry also hands unknown/private SPA fallback paths to the real router. Signed-in homepage visitors get an Account link.

Keep navigation CTAs as single anchors (`Button asChild`), with responsive visibility on the anchor itself. Hiding only a nested button leaves a nameless focusable link on mobile. Footer section headings are h2 elements.

Prerendering must start every route from the original Vite shell, not from the already-generated homepage. Analytics events remain queued immediately; the Google tag loads after window load/idle. Its third-party unused-JavaScript warning may remain.

## Requirements

- Node.js 22 or newer
- pnpm 11
- a Cloudflare account with the `llmmargin.com` zone

## Cloudflare resources

Create a D1 database named `llm-margin`, then copy the returned database ID into the `d1_databases` entry in `wrangler.jsonc`:

```shell
pnpm exec wrangler d1 create llm-margin
```

Configure these encrypted Worker secrets. Preserve the existing production values during migration so current sessions and Stripe webhook verification continue to work:

- `SESSION_SECRET`
- `STRIPE_SECRET_KEY`
- `STRIPE_WEBHOOK_SECRET`

The native Cloudflare Email Sending binding and the non-secret values `APP_BASE_URL` and `EMAIL_FROM` are defined in `wrangler.jsonc`.

## Local development

Copy `.dev.vars.example` to `.dev.vars`, fill in development-only values, and run:

```shell
pnpm install
pnpm dev
```

The local D1 schema can be applied with:

```shell
pnpm exec wrangler d1 migrations apply llm-margin --local
```

## Validation and deployment

```shell
pnpm build
pnpm deploy
```

The deploy command validates the TypeScript projects, builds and prerenders the site, checks the Worker bundle, applies pending D1 migrations, and deploys the Worker.

## Production data migration

Import the existing `users` rows before switching the domain. Keep IDs, timestamps, Stripe IDs, plan, subscription status, interval, and current-period end unchanged. Expired or consumed one-time codes do not need to be migrated.

After importing, compare the source and D1 row counts and spot-check the Stripe fields. Then verify the Worker preview URL before adding the custom domains.

## DNS cutover

Only after the Worker preview passes the health, login, billing, and representative-page checks:

1. Remove the old Replit DNS records for the apex and `www` names.
2. Attach `llmmargin.com` and `www.llmmargin.com` to the Worker as Cloudflare Custom Domains.
3. Verify HTTPS, authentication, checkout, customer portal, and Stripe webhook delivery.
4. Stop the Replit deployment after the Cloudflare site has remained healthy.

Cloudflare creates the DNS records and certificates for Worker Custom Domains. Keeping the Stripe webhook path at `/api/stripe/webhook` avoids changing its public URL during cutover.

## Rollback

If a critical issue appears immediately after cutover, remove the Worker custom domains and restore the prior DNS records while the Replit deployment is still available. Do not delete the Replit deployment until the Cloudflare production checks are complete.
