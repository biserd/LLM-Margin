# Daily SEO in local Codex

Use `$seo-autopilot`, `$blog-refresher`, and `$seo-title-optimization` every run. Read their pinned instructions under `.agents/skills/`, the product context, keyword map and recent SEO records. The production site is https://llmmargin.com. Use the existing local checkout, GitHub login, and Wrangler login. The owner authorizes publishing qualifying edits. Skip upstream approval, outreach, purchases, and drafts.

1. Run `python scripts/seo/research.py` from the LLM Margin repo and inspect the findings. Use connected sources and built-in web search where available. Check indexing and AI visibility only with direct evidence of the relevant surface. Keep unavailable data marked unchecked. Maintain the keyword map and flag overlapping intent. Fix verified production issues. Add a comparison only when its distinct intent and claims have evidence.
2. Check for a blog refresh using the latest available Search Console page/query data. Apply the positions 8–20 rule and inspect the top three current results. Without qualifying data, record the skip. Preserve URL and voice.
3. Review SEO titles and H1s against rendered pages, the keyword map, product behavior, and current search results. If Search Console is connected, use the latest complete 28 days and compare CTR by position and device. Otherwise publish clear editorial fixes, such as a missing, misleading, duplicate, stale, or mismatched title or H1. Record the specific issue and leave CTR, impressions, clicks and rank unchecked. Combine changes to the same page and skip rewrites of titles pending measurement. A day with no qualifying edits is valid.

Use a clean, current checkout based on GitHub main. If another run is active or the checkout contains unrelated changes, leave those changes alone and log the reason. Before a release, record the current production Worker version and expected title, H1, canonical or body change for each URL. Run `pnpm build`, inspect the built HTML, and run relevant repo tests. Push only verified changes. Then run `pnpm exec wrangler deploy` using the existing login and verify the live URLs plus `node scripts/verify-public.mjs`. If repeated checks confirm a regression caused by the release, restore the previous Worker version and revert only the job's own commit.

Commit a concise dated record under `seo/runs/` with the three stage outcomes, sources or blockers, before and after metadata and metrics where measured, changed URLs, and deployment status. Keep a title measurement pending for 28 complete post-release days when baseline data exists. For editorial title fixes without data, wait at least 28 days before revisiting unless correcting a verified regression. Use scoped permissions available to the task and report any exact deployment or network restriction that prevents completion.
